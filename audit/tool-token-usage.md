# 工具定义 Token 用量统计

本文记录 4 台内置仪器（DM3058、DG1022Z、33600A、MSO5000 全选件）在三层工具结构下的 Token 消耗。

---

## 各层级汇总

| 层级 | 包含工具 | 工具数 | 原生 Tokens | OpenAI 包装格式 Tokens |
| --- | --- | ---: | ---: | ---: |
| **第一层（Basic）** | 5 个静态管理工具 | 5 | 910 | 940 |
| **第二层（Instrument）** | 4 台仪器的概览工具 | 4 | 698 | 722 |
| **待命合计（第一层 + 第二层）** | 基础管理 + 仪器概览 | **9** | **1,608** | **1,662** |
| **第三层（推荐 Scope）** | 激活各仪器 `default_capabilities` | 394 | 53,126 | 55,490 |
| **推荐工作集合计（含前两层）** | 9 个管理/概览 + 394 个命令工具 | **403** | **54,734** | **57,152** |
| **第三层（全量 `["*"]`）** | 4 台仪器所有逻辑命令 | 1,489 | 192,299 | 201,233 |
| **全量合计（含前两层）** | 9 个管理/概览 + 1,489 个命令工具 | **1,498** | **193,907** | **202,895** |

- 连上 4 台仪器但未激活具体 Scope 时，工具定义仅占 **1,608 tokens**。
- 激活日常推荐 Scope 时，总开销为 **54,734 tokens**（OpenAI 包装格式为 57,152），低于 64k 上下文水位。
- 若使用 `["*"]` 全量展开 4 台仪器的所有功能，工具定义会达到 **193,907 tokens**。

## 对比：未折叠、扁平全量暴露

在未做三层按需加载和通道折叠的早期扁平方案中，`ch1.*` .. `ch4.*` 各自生成独立工具，4 台仪器共生成 **1,779 个工具**，仅工具 Schema 即占用 **230,308 tokens**。

通过以下几项调整降低了开销：
1. **三层渐进加载**：`instrument_load` 只注册单台仪器的二级工具，具体命令等调用二级工具传入 `capabilities` 时再注册。
2. **通道折叠**：对称的 `ch1.*` .. `chN.*` 合并为带 `channel: 1..N` 参数的单个逻辑工具（单通道仪器隐藏 `channel` 参数），4 台仪器的逻辑工具数从 1,779 降至 1,489。
3. **按功能域划分 Scope**：按 `vertical`、`waveform`、`trigger`、`measure` 等功能分组，便于按当前任务只打开需要的子集。
4. **精简工具名前缀**：使用 `mso5000`、`dg1022z`、`dm3058`、`keysight33600a` 作为 `tool_name` 前缀，避免把完整 `*IDN?` 型号串拼进每个工具名。

---

## 统计方法

- 直接调用 `host/instruments.js` 中的 `InstrumentTools.registerInstrument` 与 `activate` 生成真实的工具定义对象。
- 使用 DeepSeek 官方 BPE 分词器（`tokenizer.json`，通过 Python `tokenizers` 库加载）对工具的 `name`、`description`、`parameters` JSON 序列化结果进行分词统计。
