# 大模型上下文开销实测：三层工具模型下的 Token 用量分析

> 为什么我们一定要做“三层渐进加载”和“通道折叠”？这篇实测报告用真实数据回答。

在设计本插件时，我们面临的最大痛点之一就是**大模型的上下文窗口与注意力极限**。现代实验室仪器命令繁多（仅一台全选件 MSO5000 示波器就有近 900 条指令），如果一股脑把所有仪器的命令全部变成工具喂给大模型，会发生什么？

为了得到精确的第一手数据，我们搭建了真实测试：将 4 台典型仪器（DM3058 万用表、DG1022Z 发生器、33600A 发生器、MSO5000 示波器全选件）全部载入，使用 DeepSeek Tokenizer 进行严格分词计量。

---

## 三层结构各阶段开销实测

| 加载阶段与层级 | 暴露给模型的工具总数 | 原生 Token 计数 | OpenAI 包装格式 Token 计数 |
| --- | ---: | ---: | ---: |
| **第一层（Basic）**：5 个全局基础管理工具 | 5 | 910 | 940 |
| **第二层（Instrument）**：4 台仪器专属概览工具 | 4 | 698 | 722 |
| **日常待命合计（Level-2 总计）** | **9** | **1,608** | **1,662** |
| **第三层（Tools·日常推荐 Scope）**：仅展开测量/波形/垂直等常用组 | 394 | 53,126 | 55,490 |
| **第三层（Tools·极端全量展开）**：4 台仪器所有能力全部激活 | 1,489 | 192,299 | 201,233 |

### 核心结论对比

- **日常待命极其轻量**：连上 4 台仪器后，在模型未展开具体命令前，两层工具总计仅消耗 **1,608 tokens**，几乎不占用宝贵的上下文。
- **推荐工作集安全可控**：当模型根据实验任务激活推荐的常用 Scope（如示波器激活垂直/水平/触发/测量，信号源激活基础波形）时，4 台仪器的工具总开销为 **54,734 tokens**（原生）/ **57,152**（OpenAI 包装），**稳稳控制在 64k (65,536) 的安全水位线以内**。
- **杜绝盲目全量加载**：如果将全部功能一网打尽（使用 `["*"]`），4 台仪器的工具定义将暴增至 **193,907 tokens**，直接打穿大部分主流模型的上下文上限。这印证了我们的设计初衷：**命令必须按需激活，绝不能作为默认行为**。

## 优化策略背后的工程思考

### 早期方案的困境
在早期的扁平化设计中，每台仪器的所有命令直接摊平，而且 `ch1.scale`、`ch2.scale`、`ch3.scale`、`ch4.scale` 各占用一个独立工具。4 台仪器加起来足足有 **1,779 个工具**，仅工具 Schema 就要吃掉 **230,308 tokens**，大模型根本无法正常推理。

### 当前架构的四重优化
1. **树形渐进展开（Progressive Disclosure）**：遵循 basic → instrument → tools 的认知顺序，连上设备只注册门面工具，用什么能力才展开发什么能力。
2. **语义通道折叠（Channel Folding）**：把 4 个物理通道的重复命令合并为一个带有 `channel: 1..4` 参数的逻辑工具，单通道仪器自动隐藏该参数。仅此一项就将 4 台仪器的逻辑工具数从 1,779 压缩到 1,489，消除了大量冗余 Schema。
3. **基于能力而不是基于物理通道划分 Scope**：将工具划分为 `vertical`、`waveform`、`trigger`、`measure`、`modulation` 等直观的工程功能组，符合工程师在实验台上的思维逻辑。
4. **规范化设备族命名**：统一使用 `mso5000`、`dg1022z`、`dm3058`、`keysight33600a` 等简明的前缀，避免冗长的 IDN 字符串挤占 token。

## 实测环境与计量方法说明

- **真实数据生成**：测试直接调用 Node 插件层真实的 `InstrumentTools.registerInstrument` 和 `activate` 函数生成具象的工具对象，绝非手工纸面推算。
- **分词工具**：采用 DeepSeek 官方 BPE 分词器（`tokenizer.json`），使用 Python 专用的高效 `tokenizers` 库直接统计，避免引入庞大的第三方推理框架误差。
- **统计口径**：准确计量了导出到大模型 System Prompt 中的 `name`、`description` 和 `parameters` 的完整紧凑 JSON Schema 文本；报告中以原生 Token 数为主指标，同时附带 OpenAI function 包装格式作为上限参考。
